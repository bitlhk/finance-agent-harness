# Credit-card reference Runtime：职责与验收边界

本组件供客户经理使用。Python Runtime 执行业务编排，不签发生产身份，不办理授信、交易或权益领取。

| 环节 | Harness／受管宿主负责 | 信用卡 Runtime 负责 | 当前边界 |
|---|---|---|---|
| 身份与来源权限 | 签发并校验可信 principal、subject、Host session、有效期、scope；通过当前会话回调获取凭据 | 受控注入 SnapshotSource；每次 read_current 核对客户、Case、时点、可见来源及快照摘要 | 私有回环 bearer 只保护传输，不能代替用户身份；真实 SSO／ACL 未验收 |
| 会话生命周期 | 通用会话创建、绑定、过期、撤权及当前来源会话 | 按可信绑定保存 reference 操作、会话与对话目录；不采信模型提交的角色或 URL | reference 内部 session_ref 不是生产登录凭据 |
| 历史与回放 | 授权谁能读当前会话和证据，并在披露前复核当前权限 | 保存业务线程、推荐、父运行、幂等操作及来源版本；不同对话上下文独立 | Runtime 的业务存储不代替公共证据账本；生产统一回放关联尚未安装验收 |
| 停止、取消和迟到结果 | 受管实例的启动、停止、回收及调用期限 | 服务协调器记录取消／超时终态，限制调用，迟到结果不覆盖终态 | HTTP 断连不等于用户取消；宿主须执行资源回收 |
| 业务语义 | 受管 Provider 声明只读能力及必要权限 | 查询当前账务、冻结预测、资格检查、权益排除和匹配说明 | 不批准额度，不自动领取；预测制品保持 HOLD |
| 模型与工具 | 部署方绑定固定模型、工具、Worker 和来源，不从用户输入获取任意地址 | 原生 openJiuwen ReAct／Workflow；结果保留来源、版本与调用记录 | OneRec 权重不分发；真实模型质量、生产容量与性能未验收 |

## 部署装配要求

1. 宿主先验证当前经理、当前业务客户和有效会话，再构造 Provider 所需的可信授权及来源绑定。
2. SnapshotSource 必须在每次读取时重新授权；仅比对 SourceBinding 与快照摘要不足以实现生产撤权。
3. 启停、调用、来源会话、构建 Lock 和业务回执须由受管宿主建立可复查关联。当前接口及合成 HTTP 测试只证明对应组件边界，未证明目标环境的受管 Host 已安装通过。
4. 浏览器或模型传来的 session_ref、客户 ID、scope 或 URL 只能作为请求数据，由宿主与可信绑定核对。
5. 生产 SSO／ACL、外部服务、干净离线安装及跨平台性能继续记为 NOT_RUN；缺少绑定应阻断，不能用参考令牌宣称生产准入。

## 测试口径

公共 JSON 契约 CI 使用 Python 3.10／3.12；信用卡 Python Runtime 要求 >=3.11.4,<3.14，独立 CI 以3.11／3.12／3.13构建 wheel并安装到新 venv，使用本包原生测试及本机合成 HTTP／模型端口。该 job 不使用真实模型凭据，不将公共3.10合同绿灯解释为 Runtime支持3.10。测试报告保留跳过项，生产边界保持未验收。
