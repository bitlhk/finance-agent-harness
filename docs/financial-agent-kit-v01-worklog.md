## 修改前的兼容决定

1. 保持四合同的现有 JSON 外壳；财富数据使用独立版本的合同与公共模块，不给原响应静默加字段。
2. 原 Provider/Pack 继续存在；新切片通过显式映射消费原能力，不把员工和客户能力直接改名合并。
3. 实授不足或身份无法验证的调用关闭访问。仅声明 requiredScopes 的旧配置需补可信宿主授权，这是有意收紧。
4. 旧 Checkpoint 无明确输入收集证明时不得放宽改参。文件存储继续使用，不宣称多节点或跨进程互斥已验收。
5. 默认演示离线受控模式。真实模型和数据源需显式配置，权限与数据不足明确失败，不用默认零补齐。

## A/B 回归说明

复用了宿主确认、单机 FileTaskCheckpointStore、UNKNOWN 查证、digest 验证及现有 CI；未合并 PR #2。
新增 InputCollectionProvider 由 Adapter 明确证明本地收集阶段。无 taskRef 本身不是证明；创建响应丢失后保留原记录，禁止自动重试创建。
旧有固定参数改变继续拒绝；待确认任务可由宿主拒绝本次授权后显式发起新预检，不能把拒绝授权称为银行任务已取消。PROCESSING/UNKNOWN 不允许该捷径。
BoundFinanceProvider 的 Grant 必须由可信宿主解析实授、主体、用途和会话；不是模型输入。EA 旧四参数 Config 保留源码兼容，但未注入 adoption-owner 对应就 fail-closed。现有旧 live 示例因此不再作为已授权路径，新的接入说明提供迁移点。
回归过程中修复了新测试缺少 inputSchema.type、Client 内部 text 重载遮蔽等编译/Fixture问题；未放宽确认或授权断言。文件恢复/并发仍是单 JVM 新实例和双控制器测试，不声称多进程/多节点已验收。
