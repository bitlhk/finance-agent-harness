# Finance Harness

将业务方法、能力合同和企业数据接线装配为可运行、可验收、可维护的 Agent。业务开发不从复制一套授权、观测和历史存储开始。

[完成第一个 Agent](first-agent.md#materials) · [取得开发材料](first-agent.md#materials) · [架构与 API 参考](developer-guide.md)

## 从任务到交付

需求与验收 → 复用资产／补齐缺口 → 方法和案例 → 装配与准入 → 运行证据 → 发布、停止与历史。

首个任务是**合成只读月度收支核对**：用同一份方法和能力构建手机、ATM 浏览器模拟两个入口。先跑通现有资产，再做一次隔离的方法正文修改；不是只展示预置模板，也不新增银行接口。

图表示职责和依赖，不是部署顺序。Builder 选择并锁定资产，**不授予银行权限**。Runtime负责模型与工具循环；Host提供可信身份并实施检查，Provider按合同返回事实。Skill不能替代授权代码，目录也不等于实际安装。

## 这套流程解决什么

| 开发者的问题 | 可复用的现有机制 | 本例如何看见结果 |
| --- | --- | --- |
| 每个入口都要改一遍吗？ | 同一方法、合同和Provider声明被两个consumer消费 | 两端Lock引用同一方法版本与正文摘要；实例Lock各自独立 |
| 组合不兼容为何要等编译后才知道？ | 构建前兼容检查与显式依赖影响 | `COMPATIBLE`或明确拒绝；未知影响需审阅，不自动复用资格 |
| 谁以什么权限查了什么？ | 阶段三可信执行绑定及ENTRY/RETURN/PROJECTION证据 | 对象/主体摘要、期间、Host、Lock、有效期、结果摘要可关联 |
| 模型失败或实例停止后怎么办？ | 事实与失败状态保留、平台历史权限读取 | 停止后可按权限读原记录，不重新查询银行或生成模型 |

阶段三的收益不是“又多一张日志”：改期间会重新判断，撤权后的未释放结果被阻断，必要审计写入失败不放行；排错能区分缺参数、授权、来源与证据故障。详见[运行与可信证据](first-agent.md#step-6)。

## 已实现范围与边界

本例基于 H `4771cfe5` / B `0a38ec18`，OpenJiuwen Java `0.1.15`、合成只读收支、手机与ATM浏览器模拟。已完成两端普通SSO首次查询、本人停止与历史读取；这是限定切片，不是真ATM或所有Runtime安全一致性验收。

225次候选测试执行、7组代表安装准入、2条普通SSO路径是不同证据，不能混成一个成功率。云CI未启动的缺口已被发布审批明确接受，不记为CI通过。一次资产复用也不能证明普遍提效百分比。

**安全可信已接近本试点目标，不等于生产银行安全认证。** 查询授权不等于历史查看权；本地合成策略摘要不是银行授权快照，SHA不是签名或WORM。外部不可绕过隔离、独立凭据托管、防篡改审计及真实银行接入仍待验证。未集成NVIDIA OpenShell／Sentry／prover，不保证任意模型替换后的行为等价。
