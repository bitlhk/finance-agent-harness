# 架构图修订说明

总览图版 V0.3.6，2026-09-08；运行调用图保留 V0.2.1 内容。仅修图与说明，不新增引擎、不改变执行代码。

本版采用已确认的企业适配与边界箭头布局；发布与验证结果单独记录，不表示运行代码或能力成熟度升级。

- `architecture.svg`（内部组件图）：横向布局，主体组件居左，工程支撑在 Harness 内右侧纵栏，Builder 在框外最右侧跨层纵栏。北向箭头从 Harness 上边界向上接 Agent 运行环境，南向从下边界向下接企业系统；仅表示接入方向，不是调用顺序。Builder 虚线标为装配与验证集成，不画内部执行箭头。
- `lifecycle.svg`（运行调用图）：保留原文件名和已有内容；展开一次受管只读调用的 BoundFinanceProvider、源身份与结果返回，供需要执行细节的读者单独阅读。

## 本次澄清

1. 总览表示代码／资产归属，不是部署拓扑。Integrator 归 Harness，实际嵌入宿主，图中只画一次。
2. 四类可复用内容以中文用途为主：专业工作方法、业务能力与工具、使用角色与范围、统一业务数据定义；英文组件名小字保留，现有目录及合同不改名，每框注明实际消费者。
3. 资产与 Core 之间用关系说明条代替交叉箭头；Core 不统一加载资产、不解释 SOP、不依赖具体银行实现。
4. Builder 纵栏从 Agent 顶部贯穿至企业系统连接区域底部，表示构建配置覆盖面：运行环境、Harness 内容、Provider 连接、应用制品。它不接管企业系统、不参与业务调用。虚线标为装配与验证集成；实际安装由生成 Host 初始化时调用 Assembler。
5. 北向与南向箭头均从套件边界引出，分别向上和向下，不从 Integrator 或 Provider 内部引出；授权检查、双向调用返回与 Lock 生成分别留在运行图和构建说明中。
6. 不改变原有边界：Profile 不授权，内容检测不代替业务授权，待适配不等于已验证。
7. Integrator 与 Provider 使用一致的灰色底和边框，Core 保持独立的浅红色强调公共基础；不以颜色编码验证状态。
8. Core 为公共合同与执行基础；Provider 注明参考实现与客户扩展。工程支撑改为框内右侧纵栏，纵向覆盖主体组件，不并入 Core、不移出套件；栏内区分初始化时的装配安装与开发／验收／回归时的测试评测。与外部 Builder 保持两层归属。
9. 第四类内容保留中文用途“统一业务数据定义”，英文组件名统一为 `Contract`，指领域公共合同；Core 通用合同仍归 Core，不新增模块。
10. 南向表述为企业适配，CRM、ERP 等仅为系统类别示意；当前参考实现和验证范围不变，不宣称新增连接器。
11. 图内删去讨论性解释，保留职责、消费者和关键约束；候选 API 稳定性、Core 不解释 SOP 等边界在配套正文中说明。

已实现/待适配用框内状态文字表达，不能从连线颜色推断验证范围。技术实现和归属解释见开发指导，业务成熟度没有因换图提升。
