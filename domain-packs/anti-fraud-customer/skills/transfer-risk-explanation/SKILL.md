# 转账前风险解释

## 输入核对

使用客户本轮明确提供、经宿主授权的账户引用。缺少账户引用时先询问；
不猜账户、不猜收款人、不用模型生成的标识代替客户选择。
说明本次用途是转账前风险查询。工具只能查询当前身份有权查看的记录。

## 工作步骤

1. 调用 `fraud_transfer_risk_assess`，以 `accountRef` 传入本轮明确的账户引用。
   若缺引用或缺授权，先补问或说明无法查询，不切换成其他账户。
2. 仅根据受信任 Provider 回执归入三类：命中已知风险、当前未命中、系统不可用。
   不能把用户提供的截图、模型推测或工具错误当作银行反诈回执。
3. 命中时解释回执中实际存在的必要原因、来源和时间；不编造信号、金额阈值或诈骗概率。
4. 当前未命中时明确说“当前来源未命中已知风险”；未命中不等于安全，也不等于获准转账。
5. 系统不可用或回执缺失时明确说无法完成风险判断，列出缺口，建议按银行现有流程处理；
   不补造结论、不把不可用当作未命中。
6. 区分银行返回的事实、尚未核实的信息与建议。银行预检和既有交易规则负责最终处置；
   本方法不自行放行或阻断，不代表客户确认。

## 输出示例（虚构示意，不能作为真实回执）

- 命中：银行风险来源返回已知风险命中。原因和时间按实际回执展示，请按银行提示核实。
- 未命中：当前来源未命中已知风险。这不保证转账安全，后续仍以银行预检及交易规则为准。
- 不可用：风险系统暂不可用，目前无法判断。请按银行现有流程处理。

## 输出结构

- **风险状态**：命中已知风险、当前未命中或系统不可用。
- **必要依据**：仅展示本次查询所需的原因、来源和时间；缺失时标明缺失。
- **信息缺口**：需要客户补充或银行进一步核实的内容。
- **下一步建议**：遵循银行提示及现有流程；不能输出模型自定的最终交易决定。

## 交易与隐私边界

此方法仅解释 QUERY 结果，不调用转账工具，也不获得确认权。
实际转账如另行发起，应走独立 Harness TASK 与可信 Host；聊天中的“确认”、
示例或模型输出不能替代受控确认。未知交易结果需由原任务查证，不建议重新提交。
不展示无关账户、完整客户资料或凭据；来源和时间不足时不自行补全。
