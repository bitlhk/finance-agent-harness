# 开发一个 Harness 业务组件

这里的“开发 Harness”是扩展已有套件，不是再复制一个 Core。先打开业务资产，选定真实组件和版本。

## 先看关系，再选改动

在“工具与依赖”中，Skill 的 `allowed-tools` 与本组件工具声明对照展示。
这是声明检查，不是自然语言依赖识别：正文提到的未知工具不会被自动推断成已绑定工具。
未声明、无法解析、未在当前绑定中找到，都需要开发者核对。其他包可能提供该工具，因此缺项不是全局不存在的证明。

工具输入可能直接内联在 `pack.yaml`。公共 `CapabilityResult` 是返回外壳，不是所有领域输出的完整定义。
Provider 对接实际企业接口；Skill 不替代实现，Profile 和所需权限声明不代替实授。

## 路径一：修改专业方法

1. 打开真实资产，查看 Skill、工具声明和现有验证范围。
2. 点击“定制业务方法”，派生自己的草稿。修改专业步骤与输出，并添加至少一个覆盖本次修改的案例。
3. 增加工具依赖时重新绑定；未准入能力不能凭工具名称直接调用。
4. 保存，运行已有检查与试跑。核对新方法、案例及版本确实参与，不以旧报告替代。
5. 发布新版本，打开其组成页，对照下载 ZIP。用这个版本创建 Agent。
6. 核对该 Agent 的安装 Lock、工具调用及输出。旧 Agent 不自动改变。

练习：保留收支工具与 Provider，把方法改为“收支信息缺口核验”，增加缺少分类来源的案例。
既要说明现有事实，也要说明缺口；不能把缺失金额填零。记录改动文件、测试结果与求助次数。

## 路径二：开发新的企业来源或能力

1. 从维护者取得可读取的固定 Harness Git 提交、已验证依赖和隔离测试环境。页面源码链接固定提交，不指向滚动 main。
2. 若业务含义及合同不变，优先只替换 Provider。新增业务含义才增加能力声明及必要领域合同。
3. 按页面实际引用定位能力包 `pack.yaml`、可用的装配声明与 Provider 工程；不要新建同义协议。
4. Java Provider 实现 `FinanceProvider.query(CapabilityRequestV1)` 与 `executeTask(CapabilityRequestV1)`，返回 `CapabilityResultV1`。未支持的办理必须明确拒绝；不要照搬一个默认成功实现。
5. 参考既有受管理工厂接线。宿主提供可信上下文，公共授权包装器核对实授；Provider 另外核对源身份与接口语义。
6. 在对应 Maven 模块新增测试，覆盖正常、错身份、撤权、缺数、精度与坏响应。有副作用协议另测冻结、可信确认及结果不确定后的查证。
7. 编译、测试并提交制品及声明，由维护者完成受管理安装和目录准入。不能上传任意 JAR 后自动运行。
8. 在 Builder 选中已准入组件及连接，构建 Agent，核对实际安装和行为。若需修改 Builder 业务分支，先记录公共缺口并评审。

运行命令必须对应开发者实际新增的测试，不预填不存在的类：

```sh
# 在 Harness 仓根目录；用实际模块路径和新增测试类替换两个占位值
mvn -B -ntp -pl <Provider模块路径> -am -Dtest=<新增测试类> -Dsurefire.failIfNoSpecifiedTests=false test
# 检查该模块 target/surefire-reports，确认新增类与用例数量非零
mvn -B -ntp verify
```

上述定向命令允许依赖模块没有匹配测试，不代表目标模块可以零测试通过；必须查验报告。
完整验证需要 JDK、Maven 和当前 pom 指定的依赖。涉及真实 Smoke 的配置与权限单独准备，不在普通回归中启用。

## Trace 应怎样接

公共工具调用观测参考 `ObservedFinanceProvider`，授权参考 `BoundFinanceProvider`，输出目的地使用 `ObservationSink`。
页面提供当前固定提交中实际存在的源码链接及测试参考。它们是开发入口，不是组件已满足全部要求的认证。

Provider 使用现有观测扩展补充来源请求尝试和业务状态；来源名称参考 `ReferenceObservationLabels` 的操作标识、方法与路由模板。
不要记录真实账户路径、密钥、完整客户正文或隐藏推理。尝试、已发送、阻断、异常、业务终态必须区分。
观测失败不能把已经完成的业务改写成失败。新增包不会自动获得尚未接线的来源内部观测。

验收时沿同一请求检查工具、来源、版本和结果；历史查看不能重执行业务。
至少补一个来源故障或拒绝案例，并验证记录缺口可见。专业质量评测与执行边界测试分别报告。

## 交付清单

- 固定版本、维护人、字段依据、所改文件与制品摘要。
- Skill / 声明 / 合同 / Provider 的真实关系；未包含的依赖明确引用。
- 可重跑测试命令、实际数量、失败与跳过项，新案例反向破坏测试结果。
- 具体 Agent 的安装和执行证据；不把单个 Lock 作为包的固有属性。
- 独立开发者实填耗时、环境等待、求助和卡点。AI 自测不能代填独立接入通过。

这是一条受管理开发路径，不承诺所有新协议仅靠上传一个包完成。页面不提供在线 Java 编辑、任意代码执行或新的发布机制。
