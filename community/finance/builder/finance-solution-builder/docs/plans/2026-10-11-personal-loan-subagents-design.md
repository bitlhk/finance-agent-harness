# 个人贷款审核：动态 Subagents 桌面体验设计

## 目标

将个人贷款审核演示改为一次上传完整合成材料包后，按受控测试政策实际完成四项已安装审核能力，并在桌面 Web 中以 Codex 风格的动态 Subagents 列表展示实际任务状态。

## 业务边界

- 政策为受控演示政策，页面必须显示其为测试政策，不得表述为真实行内政策。
- 每条政策必须包含政策标识、版本、生效期、审批状态、适用范围和参数来源。
- 所有输出仅为人工复核工作底稿；不得作出审批、拒绝、授信、定价或放款决定。
- 右侧状态和耗时只能由后端实际事件更新，不能使用前端计时器、预设延时或伪造完成状态。

## 单次上传材料包

演示包使用一个 JSON 文件，包含 11 类合成、脱敏测试材料：身份证、户口本、结婚证、贷款申请表、收入证明、流水明细、个人所得税完税证明、社会保险参保证明、不动产权证书、不动产信息查询结果、贷款结清证明。

材料包上传后先执行完整性和格式校验。通过后，编排任务才可分派四个专业审核能力：借款人主体资格核验、收入交叉验证、资产负债核验、偿债能力测算。

## 受控演示政策

新增版本化个人贷款演示政策，显式记录：

- 借款人年龄与期限组合限制；
- 抵押物价值与申请金额的适用限制；
- 收入、流水、个税和社保的交叉验证口径与偏差容忍；
- 月供收入比、压力测试和例外处理要求。

审核结论应引用具体政策 ID 和版本。政策不适用、材料矛盾、未核验或规则缺口均应转为人工复核事项，不能被模型自行补全。

## 桌面交互

页面保留左侧案件/材料区和中间流式主对话；右侧替换为紧凑的 Subagents 任务列表：

```text
已开启 · 2
 ◉ 材料归集与完整性校验                 6s
   正在建立证据索引
 ◉ 收入交叉验证                         4s
   正在比对流水、个税与社保

完成 · 3
 ✦ 借款人主体资格核验                   12s
 ✦ 资产与负债状况核实                   10s
 ✦ 偿债能力测算                         8s
```

任务进入 `RUNNING`、`COMPLETED`、`NEEDS_HUMAN_REVIEW` 或 `FAILED` 由服务端的 AG-UI 自定义事件驱动。单击任务才显示其输入材料、政策版本、关键发现、证据数、结论与人工复核动作；原始规则和回执默认折叠。

## 完整流程

1. 编排 Agent 校验材料包、受控政策和能力安装状态。
2. 编排 Agent 发出材料处理任务事件。
3. 四个专业能力按实际依赖执行；偿债能力测算等待收入核验完成。
4. 每个能力的真实执行结果更新对应 Subagent。
5. 编排 Agent 仅在四项任务均终态后流式汇总审核建议和人工复核交接事项。

## 验收

- 桌面终端中一次上传完整材料包后，四项专业能力均产生真实执行记录。
- Playwright 可观察到 Subagent 从等待到运行/完成的事件驱动变化。
- 所有结论均回链到测试政策和材料证据。
- 页面不展示未经执行的专业任务为“已完成”。
