# Smart Audit 三栏审核工作台设计

## 目标

把个人贷款审核体验从“生成一份长底稿”调整为可感知、可追溯的银行审核协作工作台。桌面端在一次上传材料包后，应同时呈现案件资料、AI 主对话和 Subagents，并清楚区分系统核验完成与人工授信复核。

## 用户可见结构

### 左栏：案件资料

- 固定宽度，显示材料包接收状态、材料数量、解析字段摘要和材料完整性。
- 原始 JSON/OCR 内容默认收起；展开后才能查看完整原文。
- 不重复显示 Agent 状态，避免与右栏竞争注意力。

### 中栏：AI 主对话

- 审核中保留流式文本，并在消息顶部显示编排器正在执行的业务化阶段。
- 最终结果先显示“系统核验完成，待人工复核”的简洁摘要；完整审核工作底稿、规则和原始回执保持可展开。
- UI 使用业务名，而非 capabilityId、内部索引或 `COMPLETED` 作为主要语言。

### 右栏：Subagents

- 宽度固定并与其他两栏同屏；小于桌面断点时才转为抽屉。
- 每位 Agent 只在这里展示一次，列出状态、材料数、规则数、耗时和一句业务化说明。
- 展开显示任务范围、业务化结论、证据入口、依赖关系和适用政策版本。

## 状态与安全边界

状态仅表示受控核验过程，不能暗示审批结论：

`材料已收齐 → 系统核验进行中/已完成 → 待人工复核交接`

“系统核验完成”须紧邻“非审批结论、必须人工复核”的提示。演示材料只使用模拟数据；原始材料默认折叠。

## 数据流

复用 AG-UI 中已有的 `finance.subagents`、`finance.reviewTeam`、流式文本和 `finance.evidence` 事件。前端仅把事件转换为业务化展示数据和时间线；不添加伪造的 Agent 或审批结论。每个 Agent 的材料数、规则数、依赖关系由受控场景静态映射和运行状态共同决定。

## 验收

1. 1920px 视口中三栏同屏，Subagents 不落到页面下方；1280px 仍可通过固定/抽屉方式访问右栏。
2. 一次上传 11 份个人贷款演示材料后，左栏显示解析摘要，原文默认折叠。
3. 运行时主栏显示编排阶段和流式内容，右栏随真实 `finance.subagents` 事件变化。
4. 完成后四个核验任务显示为“系统核验已完成”，案件流程进入“待人工复核交接”。
5. 展开收入核验专员可看到业务化任务范围、材料/规则数、耗时、证据入口和依赖。
6. Playwright 完整执行上传、发起审核、展开 Agent、检查最终状态并保存截图。
