# Finance Harness：交给 dot 的浏览器回归执行脚本

目标：每次发布后，通过原页面核验六个既有卡片的拼装、运行、运行记录查看和删除。
入口：https://finance-harness.demo.linggan.top/

本文件是可交给浏览器助手逐步执行的操作脚本，不是已经执行通过的报告。
配套 JSON 的初始状态全部为 NOT_RUN。不得把工程测试成绩填写为页面验收成绩。

## 直接交给 dot 的任务

请按本脚本及配套用例 JSON 执行。使用已登录、获准测试的账号和合成客户。
只操作浏览器，不执行服务端命令，不绕过权限，不直接调用隐藏接口制造通过。
不读取或记录密码、认证头、模型密钥及其他用户资料。

先运行 smoke 的 16 组；只有另行安排完整测试时才运行 full 的 77 组。
每次只保留一个本轮运行中的 Agent，逐组完成“创建→运行→查记录→停止→删除”。
首次失败必须保留，不自动重试筛掉失败；后续人工批准的重试另起记录。

## 开始前

1. 记录时间、页面地址、发布提交号、浏览器和屏宽。提交号由发布人提供；无法核实时写 UNKNOWN。
2. 检查灵感登录保护正常。无权限、登录过期时停止，不请求管理员绕过。
3. 在“我的 Agent”记录当前 Agent ID 集合为保护清单。任何已有 Agent 都不得停止、运行或删除。
4. 确认目录仍是余额查询、财富事实描述、财富客户上下文查询、收支分析、行内转账、渠道展示偏好。
5. 记录本轮所选模型，所有组尽量相同。固定经批准的合成身份、业务月份、转账预览参数和偏好预览值。
6. 若页面不能证明为模拟环境，禁止测试办理卡片，记录 BLOCKED。不能自行编造收款账户。
7. 快速测试不做持续并发压力、故障注入或真实转账。不调整权限、超时、模型或目录以求通过。

## 每一组通用步骤

### A. 组合装配和构建

1. 从“创建金融 Agent”进入，选择用例指定 Runtime、模型和卡片。以实际卡片名称核对 JSON 中的组件 ID。
2. 展开选择摘要，确认选中的 capabilityId 集合等于 expectedCapabilityIds；收支卡包含汇总和分类两个能力。
3. 不勾选用例外卡片。隐式 Provider 依赖不等于允许额外业务工具，按实际安装清单分别记录。
4. 点击“开始构建”一次，立即记录新 buildId。只有本轮创建的 ID 才进入可清理清单。
5. 等待页面终态，不重复点击。构建失败保留阶段、错误码和截图；页面轮询结束或人工等待预算到达时记 TIMEOUT，不扩大后端超时。
6. 检查全部构建阶段和安装校验通过；不能只因“已生成”就算成功。
7. 启动并打开 Agent，确认 READY、所选模型、能力列表及模拟环境标识。无有效授权应记 BLOCKED，不伪造授权。

### B. 逐卡运行

使用独立会话测试各卡；组合测试不要只问一次余额就判其他卡片通过。

| 卡片 | 输入或操作 | 必须核对 |
| --- | --- | --- |
| 余额查询 | 查询当前授权客户的本行账户余额 | 实际调用 account.balance.query；结果及来源有效，不能只看回答文字 |
| 财富客户上下文查询 | 查询我的财富客户资料和风险等级 | 实际调用 wealth.customer-context.query；不跨客户，不输出未授权信息 |
| 财富事实描述 | 请整理当前客户的财富事实，并说明缺失的信息 | 实际调用 wealth.facts.describe；缺失信息不能编造，不要求给出购买建议 |
| 收支分析 | 查询【固定月份】收支汇总，再查看这个月的支出分类 | 两个查询能力都有实际记录；漏做一项记失败或 PARTIAL，不能由回答“完成”推断 |
| 行内转账 | 使用批准的模拟参数进入转账预览；到确认环节明确取消 | 必须确认后才可提交；本轮不点提交，不发生转账；取消后无续办 |
| 渠道展示偏好 | 使用批准的模拟偏好值进入修改预览；在确认前取消 | 不自动修改偏好；取消后状态正确 |

如果模型未调工具、反复澄清或服务失败，记录真实结果，不换问法直到成功。
参数确实缺失时可以按界面提示补入事前批准的数据，逐轮保留记录。
组合包含余额和收支时，再用一句话请求两项，检查没有漏项和能力替代。
办理无法到达预览或取消终态时不能冒称通过，也不能为了清理绕过任务恢复保护。

### C. 运行记录与只读回放

1. 保存 requestId、runId/记录 ID、buildId 和最终状态；字段不可见写 NOT_OBSERVED，不猜测。
2. 打开“运行记录”，按本轮 Agent 和时间定位。核对选中工具、参数范围、工具结果状态与最终回答一致。
3. 展开瀑布图：模型、工具、Host 的阶段顺序和耗时可读；长模型调用不应显示成几乎不可见短线。
4. 阶段重叠可能来自并发，不要求耗时相加等于总耗时；缺时间戳应显示未知，不能拿猜测值判对错。
5. 查看状态及已有结果，刷新并再次打开同一条记录。回放指读取旧记录，不是再次发送聊天或重跑任务。
6. 两次查看应保持同一记录 ID、工具事实、终态和调用计数；不能多出新运行。
7. 如果页面无法提供模型/Provider 调用计数，注明无法仅凭浏览器证明零新增调用，交由发布人关联服务端记录补证。
8. 保存截图前遮挡合成身份以外的资料；默认报告只收用例 ID、关联 ID、状态、耗时和截图路径。

### D. 停止与删除

1. 等待本轮请求终止；如有未完成任务先在正常界面取消。不要直接删除任务文件。
2. 对照保护清单和本轮创建清单，再确认 buildId。停止实例，等待显示 STOPPED。
3. 点击该 Agent 的删除入口，核对确认框 ID，只确认删除本轮 Agent。
4. 刷新列表及重新打开页面，确认该 ID 消失、运行实例不再占用名额。
5. 按现有语义检查该 Agent 的本地运行记录已清除；删除摘要可以保留，不把它当作泄漏。
6. 用保存的旧页面链接确认不能继续聊天或读取已删除的业务记录。不要尝试其他用户的 ID。
7. 删除被任务恢复保护拦截时记录 CLEANUP_BLOCKED，保留 ID 交人工处理；不能强制删除。立即停止本批后续创建，避免不断积累不可清理的测试 Agent。
8. 构建失败的产物也通过正常界面清理。最后报告所有 cleanupRemainingIds，不得漏报。

## 快速与完整覆盖

- smoke：Java 六单卡＋四查询卡组合＋六卡组合，共 8 组；Python 三单卡＋全组合，共 4 组；AgentScope 三单卡＋全组合，共 4 组。合计 16 组。
- full：Java 六卡的全部非空子集 63 组，Python 7 组，AgentScope 7 组，合计 77 组。
- 不测试声明不支持的组合为“应该可运行”。另做负向核对：Python 不可选办理、AgentScope 不可选渠道偏好及财富卡。
- 全组合覆盖不等于所有输入、所有模型、所有业务分支覆盖。TASK 提交不在这套默认脚本中。
- 当前删除器只清理空闲任务作用域；已取消任务如果仍有确认、句柄或检查点文件，也会拒绝删除。不能承诺“办理预览后必然可删除”。这类用例如遇保护，应分别记运行结果与清理阻塞，而不是把整个闭环记 PASS。需要反复执行完整办理测试时，先由运维批准隔离工作空间及归档清理流程，本脚本不代替该授权。
- “财富事实”可能有合法 Provider 依赖；安装工具集合与内部源调用分开核对，不能把依赖误判成越权。

生成新清单（不连接网站）：

```sh
python engineering/generate_browser_regression.py --mode smoke --output /tmp/finance-dot-smoke.json
python engineering/generate_browser_regression.py --mode full --output /tmp/finance-dot-full.json
```

## 输出报告

每组列出装配、构建、运行、记录查看、停止、删除的独立结果。
状态使用 PASS / FAIL / BLOCKED / NOT_RUN / NOT_OBSERVED，不把阻塞项算通过。
附首次失败、错误码、关联 ID、截图、遗留 Agent ID；按 Runtime 汇总。
分别报告“工程自动化结果”和“dot 真实页面结果”，禁止互相填充。

通过条件：选定组合可构建和运行、所需工具有证据、无越权业务调用、记录可读且查看不重执行、所有本轮 Agent 已删除、原有 Agent 未受影响。
无法观测的调用计数应单列缺口；不能因此声称完成了服务端零副作用验收。
