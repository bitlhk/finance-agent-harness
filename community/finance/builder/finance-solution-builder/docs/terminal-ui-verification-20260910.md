## 4. 余额差异的结论与修复

首轮线上回答列出五个余额，但中间三张卡片显示“未返回”。定点复核确认：

1. 完整模拟器在获授权的测试会话中确实返回 `50000.00`、`8650.00`、`920.00`，并非这三项缺字段。
2. Provider 保持 BigDecimal。展示代码的 `valueToTree` 会规范化为 `5E+4` 等形式；旧十进制文本正则拒绝这些值。
3. 新测试使用真实 BigDecimal Map 路径，在旧实现上复现 `50000.00 -> MISSING`。
4. 仅修改 `DisplayProjection`：数字使用精确十进制 `toPlainString`，限制异常指数展开；不使用浮点格式化、模型文本或其他字段补数。
5. 空值、非法文本、大额精度与零值继续验证。线上五账户逐项核对金额/币种，卡片不再出现虚假缺失。

这是**展示映射缺陷**，不是本次三项金额的上游缺数或模型编造。
结论只针对已核对的余额；未据此宣称整段模型解释及所有业务表达经过专家质量验收。
原 `live-workbench-report.json` 的14项 PASS仅证明其列出的交互，不包含五账户金额逐项一致性，因此保留为修复前记录。

修复上线后新构建生效。旧制品不静默改写，需重新构建才能获得修复。
可体验的新记录：`agent-8ed19a29eaa848b2`（多终端金融助手／余额修正版），页面构建耗时27.79秒。
制品 `service-lock.json` 摘要：`1ee27ba97d45b9a722784d3e6bdaa1ad60ab1656caa12ff129ed3fe6e2071683`。

## 5. ASR 与剩余验收边界

实际调用讯飞 IAT：官方中文录音回放识别为“明天合肥天气怎么样？”，单次5241毫秒。
浏览器 fake-device 将同一录音送入 MediaRecorder，经 HTTPS 和服务端转换后调用真实 ASR；
识别后没有自动发送，编辑后明确发送的流程已验证。凭据仅在服务端，未进入制品、源码或普通日志。
录音来源：`iFLYTEK-OP/websdk-java-demo`，提交 `04da7b394a568b785a854c1268619a596dd73f5d`，官方中文天气 WAV。
合成 TTS 的初步识别质量不佳，未计为质量通过；上述结果也不代表任意口音/噪声的识别质量。
