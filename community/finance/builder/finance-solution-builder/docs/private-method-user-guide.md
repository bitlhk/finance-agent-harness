# 在工作台选择能力并维护专业方法

适用实现：Builder `963a475f`，Harness `b55d072`。本页是操作说明，不改变现有 Harness 组件架构。

## 从业务模块开始

创建页按「场景模板 → 业务模块 → 底层框架 → 模型与界面」组织。26 类业务模块是导航目录，
不是 26 个已安装工具，也不是 26 个独立 Harness 包。当前只能构建已验证的财富事实描述与
账户余额查询；其他模块保留待接入状态，包括尚未纳入本次版本的收支能力。

点击模块详情查看其中的 Harness 能力。详情中的组合勾选与模块卡片使用同一份选择状态，
不会重复安装。能力组存在组合约束时，按组选择，不提供无法单独运行的虚假开关。
专业方法需要的能力不能被取消；身份绑定、当前实授权限检查、撤权处理和执行证据也不是可关闭的功能。

## 导入与编辑

1. 打开「业务资产」。可以新建方法、复制默认财富/余额方法，或导入 `SKILL.md`、ZIP。
2. ZIP 内须在根目录或一层封装目录中包含 `SKILL.md`。参考材料放在 `references/`，支持 Markdown/文本。
3. 在编辑页填写名称、维护人、方法正文、能力依赖和测试问题。将方法必须使用的参考文本标记为必需资源。
4. 保存当前修改，再执行校验及受控检查。未保存内容不能发布；检查之后再改正文、依赖或案例，需要重新保存与检查。

上传上限 512 KiB，最多 32 个文件，单文件 64 KiB，展开总量 256 KiB。拒绝越界路径、符号链接、
加密及超限压缩包。`scripts/` 仅可作为不执行的留存资源；声明必须执行脚本会阻断本版接入。
不会下载方法正文中的远端链接。必需参考文本会带来源摘要装入方法，不只是复制到文件夹。

导入的是当前登录所有者的私有草稿，不会向 Harness 公共仓提交，不会生成新工具或授予客户权限。
复制默认方法后也需自行验证；复制不代表已取得业务专家认可。

## 分清两种检查

| 操作 | 证明什么 | 不证明什么 |
| --- | --- | --- |
| 受控检查 | 实际 Java Host、工具、方法及参考文本装入正确，模拟读取发生，版本与记录匹配 | 真实模型的专业效果、真实银行授权 |
| 真实模型预览 | 所选服务端模型实际参与默认方法/当前方法的回答，可查看工具事实和来源 | 自动通过专业质量评审、允许发布未检查的版本 |

受控检查不是字符串扫描，也不是由浏览器上传一个 PASS。服务端构建并运行实际 Candidate，记录默认与
草稿两组结果。脚本模型明确标为受控测试。案例 `expectedTerms` 不进入模型方法正文。

真实模型预览单独选择已配置模型；它会将当前方法和合成银行事实发送到该模型，消耗模型额度。
配置不存在、停用或运行期间改变时拒绝，不回退为脚本回答。展开「事实与来源」「安装与执行证据」
可以核对原始工具事实、调用数、Runtime Lock。对于模型自行补充的评级含义、数据来源等，记为 BadCase，
不能因为对话成功就认定方法专业有效。

## 发布与用于新 Agent

1. 当前保存版本的受控检查通过后，填写如 `1.0.0`，点击「发布不可变版本」。
2. 发布冻结方法、依赖、参考材料及对应检查报告。后续草稿修改不改变已发布版本。
3. 点击该版本的「用于新 Agent」，返回创建页；确认专业方法版本、已包含的能力、模型及手机/桌面/ATM 展示。
4. 点击「开始构建」。构建成功后再启动实例并创建会话。
5. 发起一次明确的业务查询，核对回答、工具结果、来源和实际安装记录。

发布不自动替换旧 Agent。要应用修改，发布新版本并构建新 Agent。旧制品、旧安装锁和正在使用的版本
保持不变。为方法增加依赖也不授予权限；没有适配、未安装或未授权的能力仍不能调用。

## 怎样证明 Harness 和方法实际生效

「计划装配」来自选择配置，只能证明准备安装什么。运行后出现的安装 Lock 才记录实际方法 ID、版本、
摘要、工具与制品版本。需将它与本次 Agent 的 buildId、制品摘要和实际会话结果一起核对。
历史 Lock 标为该制品的已记录证据，不等于当前会话仍获授权，也不等于模型一定遵循了全部方法。

取消余额能力重新构建后，余额工具应不在安装清单中，不能仅观察页面菜单消失。方法未覆盖的已选能力
继续使用对应默认方法；例如余额专用方法不会顺带替换财富方法。

## 测试产物与故障定位

受控检查复用同一所有者兼容的 Host 种子，清理各轮检查的重复依赖 JAR，保留输入、锁和小型证据。
正式应用方法生成的 Agent 制品仍单独保留，可停止后按已有删除入口管理。备份、保留周期和旧种子清理
由维护者负责；本版没有自动删除用户历史 Agent 的全局任务。

首次装配须在实际启动工作台的同一 Python 环境安装 Harness 校验依赖：

```bash
python -m pip install -r /path/to/finance-agent-harness/engineering/requirements-conformance.txt
```

缺少日期格式验证器会在 `harness_contracts` 阶段明确失败，不能跳过该阶段。构建失败先看实际阶段日志；
模型预览失败先检查服务端连接状态；版本冲突需重新打开当前草稿；不可变版本摘要不匹配需停止使用并交维护者核查。

维护者复现入口见 [实现与验证说明](private-method-assets-v01.md)。真人独立接入和业务 Owner 的专业方法评审
需要分别记录，本页与 AI 自动测试不能代签。
