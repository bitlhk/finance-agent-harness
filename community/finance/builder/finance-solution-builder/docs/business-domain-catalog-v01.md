# Finance Harness 业务目录 V0.1

## 目标

Builder 的一级入口由渠道模板改为业务浏览分类，同时保持已发布 Agent、构建合同和 Runtime 接线兼容。浏览分类允许交叉引用，不决定执行权限、依赖或装配逻辑；底层资产仍保持唯一。

界面层级固定为：

```text
业务板块 -> 任务场景 -> 能力模块 -> 运行框架 -> 应用终端
```

业务板块用于发现和组织任务，不授予权限、不改变能力可用性，也不代替构建时的目录校验。

## 六类业务板块

1. 客户经营
2. 业务办理
3. 信贷授信
4. 运营作业
5. 风险合规
6. 投研决策

`mobile-banking` 不再作为一级可见模板。它继续作为 `CUSTOMER_CHANNEL` 渠道元数据和后端兼容模板保留，已有 Agent 仍使用原 `scenarioTemplateId`、能力包引用和 Runtime 合同。

## 首批任务场景

首批只将已接入并有目录证据的六个能力包组织为四个任务场景：

| 业务板块 | 任务场景 | 能力包 |
| --- | --- | --- |
| 业务办理 | 账户与收支服务 | 账户余额、收支分析 |
| 客户经营 | 财富持有期服务 | 财富事实说明、财富客户上下文 |
| 业务办理 | 转账办理服务 | 本行转账 |
| 业务办理（应用配置） | 渠道展示设置 | 语言、大字、屏幕阅读器和无障碍展示设置 |

任务场景精确声明能力包，不按来源模块自动扩大安装范围。六张已接入卡片互不重复；其余 20 个来源模块只完成业务归类，不冒充已接入能力。

目录投影会核对每个任务场景的能力包是否存在、是否唯一且归属声明模块。引用缺失或版本不唯一时，只将该任务场景标记为不可用并从构建入口隐藏，不自动选择其他版本，也不阻断无关场景。

账户与收支服务可作为客户经营的相关任务被引用，但这不会赋予客户经理代客查询权限。没有已验证任务场景的板块显示空状态，不能直接构建。`自定义组合` 允许用户从已登记目录中明确选择能力，但不被描述成新的业务任务。

## 兼容边界

- 不修改 Task Resolution、Provider、授权、审批或运行协议。
- 不删除 `mobile-banking` 技术模板，不迁移历史 Agent。
- 不把 26 个来源模块描述为 26 个已接入能力。
- 不为填满六类目录创建占位卡片或重复能力。
- 当前构建记录仍按原模板 ID 和冻结能力引用执行；业务目录是上层组织信息。

## Smart Audit 场景

“信贷授信”现有两个独立任务场景：个人贷款审核辅助与企业授信审核辅助。它们分别引用独立 Capability Pack 和 Provider 绑定；一个候选工程不得同时安装两个 Pack。两个场景均为内部员工的材料核验和人工复核辅助，只允许 QUERY，不产生审批、额度、写回或 TASK。

目录投影只有在 Harness Catalog、Component Assembly 和 `internal-control` Host 都能声明性准入时才将场景标为可用。个人贷款的固定规则基线随候选工程冻结并在 Provider 内核验；企业场景不复用个人规则。真实 Host 身份、授权和生产材料验收仍需要目标环境独立验证。
