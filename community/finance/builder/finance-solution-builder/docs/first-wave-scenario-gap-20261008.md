# 首批业务场景 Gap 盘点

本记录区分目录浏览分类、可执行任务场景和底层能力资产。分类允许交叉引用，不参与授权或执行决策。

## 现有六个能力包

| 能力包 | 主分类 | 相关分类或属性 | 已验证边界 |
| --- | --- | --- | --- |
| `wealth-facts-description` | 客户经营 | 财富持有期服务 | 事实说明，不作推荐或适当性结论 |
| `wealth-customer-context` | 客户经营 | 财富持有期服务 | 合成客户上下文，不代表客户经理代客授权 |
| `account-balance-readonly` | 业务办理 | 客户经营可引用 | 本人账户只读余额查询 |
| `cashflow-readonly` | 业务办理 | 客户经营可引用 | 月度收支汇总与分类分析 |
| `internal-transfer` | 业务办理 | 风险合规相关 | 受控任务，保留预检、确认和结果查证 |
| `channel-preferences` | 业务办理 | 应用配置、无障碍 | 仅语言、大字、屏幕阅读器和无障碍展示设置，不是客户触达偏好 |

浏览分类不得改变上述合同，也不得把相关分类解释为已经获得相应岗位权限。

## 场景一：客户经理服务准备

可复用资产：财富事实、财富客户上下文；在任务确有需要且权限成立时，可引用账户与收支能力。

当前 Gap：

- 现有身份和数据边界是合成客户本人，不是客户经理代客访问。
- 缺少客户关系、岗位权限、服务范围和用途约束。
- 缺少固定的事实汇集、缺项说明、来源引用和服务准备摘要合同。
- 没有员工授权机制前，只能称为模拟角色试点。

第一版只验证合成客户下的服务准备，不办理业务、不生成未经证据支持的推荐。

## 场景二：信贷材料审核辅助

建议主分类为信贷授信，关联运营作业。

只读检查的 `origin/Smart-Audit` 为独立历史，当前头提交为 `afb5e05`，不能直接合并到当前发布基线。分支已有企业授信和个人贷款规则、确定性核验器、模型边界测试及 Provider 测试，但尚需原作者完成：

- 基于当前 Harness 基线重放必要提交；
- 固定材料输入、规则版本、证据定位、问题清单和人工复核输出；
- 接入当前 Builder 目录、安装准入、Runtime 资格与运行记录；
- 证明只是辅助审核，不输出自动审批或授信决定；
- 提供端到端合成案例和反馈标准。

本分支不修改 Smart Audit 代码。

## 场景三：电诈调查辅助

建议主分类为风险合规。当前资产不是空白：

- `fraud.transfer-risk.assess` 只读风险能力；
- `fraud-mining-reference` Provider；
- `transfer-anti-fraud` Domain Pack；
- 已知事件、模型辅助信号、服务失败和边界测试；
- Builder 中已有反诈转账规划输入，但明确记录尚缺完整 Host Adapter、目录绑定和独立 Eval Pack。

当前 Provider 的已知事件命中可形成标准化证据；模型分数未经银行阈值校准，不能单独触发阻断。第一批应验证风险线索核验、证据整理和人工复核，不把 Agent 输出接成生产转账放行或拦截决定。超时和失败处置由明确的银行策略决定。

## 分批交付

1. 目录收尾：核实六个能力包含义、完成浏览分类和历史兼容，并回归现有组合。
2. 服务准备试点：只用合成客户验证事实汇集、来源和缺项说明。
3. 审核与反诈接入：按成熟度分别接入一个限定任务，不在公共代码增加场景专用分支。

通用性验收口径：同一执行协议下，新增业务主要通过资产声明、Provider 适配、场景配置和案例完成；发现新的公共协议需求时单独评审。
