# 通用 Agent L1 架构设计模板

## 使用原则

L1 描述 Agent 的角色、责任、交互、生命周期和关键架构选择，不固定类、方法、完整 Schema、Prompt、表结构或
协议字段。上位架构和共享契约已经确定的内容只引用，不复制。固定输入到固定输出、无需目标理解或自主判断的
组件应优先设计为服务、Tool 或 Workflow 节点。

每份 Agent L1 必须覆盖以下内容域；可以调整章节组织，但需在文末提供覆盖映射。

## 1. 背景、目标与 Agent 定位

说明目标用户或上级 Agent、Agent 化理由、核心职责、非职责、自主判断边界、人工确认点和本期范围。

## 2. 系统上下文与交互模型

给出系统上下文图和参与者责任，说明谁发起、谁持有控制权、谁返回最终结果，以及消息、资源引用、运行元数据、
控制事件和业务响应的语义。引用适用的 Runtime 和公共契约。

## 3. 核心场景、任务类型与工作循环

描述目标理解、上下文判断、规划、能力调用、结果观察、追问、重规划、终止和异常分支。固定工序不得伪装成
Agent 自主决策。

## 4. 能力、工具、资源与语义依赖

区分 Agent 自身能力、Tool、下游 Agent、Knowledge、Memory 和外部系统，明确事实来源优先级、权限、失败和
降级策略。具体配置和调用代码进入 L2。

## 5. 上下文、状态、记忆与产物治理

说明 Session/Run 边界、状态所有者、持久化与恢复、禁止进入模型或状态的信息、产物清单、版本关系和清理责任。

## 6. 协作、运行控制、可观测性与安全

说明流式/非流式、等待输入、取消、部分完成、多 Agent 协作、用户可见证据、最小权限和脱敏纪律。不得重新定义
Runtime 已统一的事件或 Session 语义。

## 7. 异常策略、架构决策与下钻导航

给出异常矩阵、重试/降级/终止原则、关键决策、未采用方案、待确认事项，以及 L2、接口契约、测试、部署和运维
文档链接。

## L1/L2 边界速查

- 更换模型、框架、存储或语言后仍成立的责任和行为通常属于 L1；
- 类、方法、数据结构、并发算法和重试参数属于 L2；
- 调用双方必须精确解析的请求、响应、错误码、事件和文件格式属于接口或数据契约；
- 技术变化如果改变职责、所有权或风险边界，必须同步评估 L1。
